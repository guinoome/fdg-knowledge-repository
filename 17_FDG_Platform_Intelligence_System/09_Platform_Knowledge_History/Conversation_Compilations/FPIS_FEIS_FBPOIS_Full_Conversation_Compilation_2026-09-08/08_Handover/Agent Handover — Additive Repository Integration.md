# Agent Handover — Additive Repository Integration

## Mandate
Integrate this package into the local [[FDG Knowledge Repository]] without destructive replacement.

## Source authority
The existing repository remains the source that must be audited before promotion of any note to canonical status. This package is a comprehensive conversation compilation and design-decision source.

## Required integration behavior
1. Read [[FPIS FEIS FBPOIS Full Conversation Master Index]].
2. Compare with existing [[FPIS]], [[FEIS]], [[FBPOIS]], [[FDG CORE]], and related master-index notes.
3. Do not overwrite existing README, Integration, architecture or canonical notes blindly.
4. If content overlaps:
   - retain the existing note;
   - retain this new note;
   - add explicit wikilinks;
   - record whether the new note extends, refines or supersedes a specific decision.
5. Preserve [[Decision Evolution Log — FPIS FEIS FBPOIS]].
6. Keep assets in an appropriate FPIS/visual-reference location and link them from the relevant notes.
7. Promote stable principles into canonical standards only after repository audit.

## High-value principles that should not be lost
- no generic AI/SaaS visual language;
- domain-native module workspaces;
- progressive rearrangement, not progressive information loss;
- configurable experience, not configurable engineering truth;
- protected engineering semantics;
- marketing as a governed experience layer;
- Experience Composer / white-label governance;
- Fire Pump as PM Template 001, not an isolated app;
- reusable Maintenance Evidence Capture Engine;
- deterministic recommendation engine first;
- photo/OCR/3D intelligence only becomes authoritative after human verification;
- PWA offline-first first deployment;
- main technician auto-tagged from account;
- report date editable but system timestamps separate;
- client representative e-signature;
- functional in first hours, then continuous patches.
