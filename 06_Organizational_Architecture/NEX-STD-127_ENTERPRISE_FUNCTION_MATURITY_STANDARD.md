# Purpose

This standard prevents confusion between organizational knowledge maturity and current staffing or software implementation.

# Three Independent Maturity Axes

## A. Organizational Knowledge Maturity

- Initial: name or need only
- Defined: mandate and main responsibilities exist
- Strong: ownership, workflows, interfaces and controls are defined
- Very Strong: mandate, ownership, boundaries, workflows, interfaces, controls, records, competencies, KPIs, risks, escalation, supporting systems and learning loops are explicitly defined and traceable

## B. Operational Deployment Maturity

- Not yet deployed
- Ad hoc
- Repeatable
- Controlled
- Measured
- Optimized

## C. Staffing / Execution State

- Founder-held
- Shared-role
- Dedicated internal
- Outsourced
- Hybrid
- Automation-assisted
- Temporarily unstaffed

# Canonical Enterprise Function Baseline

With NEX-STD-124, NEX-STD-125 and NEX-STD-126 approved, all 16 canonical enterprise functions are classified as Very Strong in Organizational Knowledge Maturity at the enterprise-function architecture level.

This does not claim that every function has dedicated employees, complete software, statutory registrations, full SOP libraries, or mature operational evidence. Those are separate deployment and staffing claims requiring evidence.

# Evidence Rule

A Very Strong knowledge rating is a statement about completeness of the canonical organizational model. Claims about actual execution, staffing, regulatory compliance, financial accuracy, control effectiveness, or operating performance require separate evidence.

# Improvement Rule

Each function shall progressively add role descriptions, SOPs, templates, data models, dashboards, training, automation, controls, and operating evidence without changing the enterprise ownership boundary unless governance approves an evolution.
