# Purpose

This standard defines the approved reusable templates and artifacts used by Nex Core Intelligence.

---

# Core Principle

A mature organization does not depend on individual memory.

It depends on reusable systems.

---

# Artifact Definition

An artifact is a structured document or information object used to support:

- decision-making
- execution
- governance
- learning

---

# Artifact Lifecycle

```
Create

↓

Review

↓

Approve

↓

Use

↓

Improve

↓

Archive
```

---

# Core Nex Artifacts

The FDG Knowledge Repository shall maintain standardized artifacts.

---

# 1. Objective Brief

Purpose:

Define what must be achieved.

Required Sections:

```
Objective

Background

Desired Outcome

Success Criteria

Constraints

Priority

```

---

# 2. Context Package

Purpose:

Provide relevant intelligence before execution.

Required Sections:

```
Objective Context

Governance Context

Technical Context

Decision Context

Operational Context

Execution Context

```

---

# 3. Work Package

Purpose:

Convert objectives into executable units.

Required Sections:

```
Objective

Scope

Inputs

Requirements

Tasks

Deliverables

Acceptance Criteria

Risks

Dependencies

Knowledge Capture

```

---

# 4. Decision Record

Purpose:

Preserve important decisions.

Required Sections:

```
Decision ID

Date

Decision Statement

Context

Options Considered

Evaluation Criteria

Selected Option

Reasoning

Consequences

Review Date

```

---

# 5. Evolution Record

Purpose:

Document controlled improvement.

Required Sections:

```
Previous State

New Evidence

Problem Identified

Proposed Change

Impact Assessment

Approval

Implementation Result

```

---

# 6. Agent Definition Record

Purpose:

Define intelligent agents.

Required Sections:

```
Agent Name

Purpose

Identity

Scope

Responsibilities

Authority Level

Required Context

Tools

Evaluation Criteria

Lifecycle Status

```

---

# 7. Review Record

Purpose:

Document validation and approval.

Required Sections:

```
Item Reviewed

Reviewer

Date

Validation Criteria

Findings

Issues

Decision

Approval Status

```

---

# 8. Knowledge Capture Record

Purpose:

Convert experience into reusable intelligence.

Required Sections:

```
Source

Situation

Learning

Impact

Recommended Future Action

Related Knowledge

```

---

# Artifact Naming Standard

Recommended format:

```
TYPE-ID-TITLE

```

Examples:

```
STD-001-HVAC-MAINTENANCE

DEC-2026-014-PV-SYSTEM-SELECTION

AGT-003-REPORTING-ASSISTANT

```

# Artifact Quality Requirements

Every important artifact should have:

## Purpose

Why does it exist?

---

## Owner

Who maintains it?

---

## Status

Current lifecycle state.

---

## Version

Change history.

---

## Relationships

Connected knowledge.

---

# Artifact Relationship Principle

Artifacts should connect.

Example:

```
Decision Record

      ↓

Work Package

      ↓

Execution Result

      ↓

Knowledge Capture

      ↓

New Standard
```

---

# Template Governance

Templates shall be:

- reviewed periodically
- improved through usage
- version controlled
- centrally maintained

---

# Anti-Pattern Prevention

## Document Creation Without Purpose

Creating files without organizational value.

---

## Format Fragmentation

Every project creating different structures.

---

## Information Storage Without Retrieval

Saving information that cannot be reused.

---

## Template Overengineering

Creating complex templates that reduce adoption.

---

# Responsibilities

## Francis

Approves major artifact structures.

---

## Nex

Maintains reusable intelligence patterns.

Identifies missing templates.

---

## Collaborators

Use approved structures.

Provide improvement feedback.

---

# Governing Principle

Templates are not bureaucracy.

Templates are accumulated organizational experience made reusable.
