# Purpose

This standard defines the structure and usage of Context Packages within Nex Core Intelligence.

---

# Core Principle

Good decisions require complete context.

---

# Context Package Objective

A Context Package transfers enough information for reliable analysis without unnecessary information overload.

---

# Context Package Model

```
Objective

+

Background

+

Current State

+

Constraints

+

Evidence

+

Expected Output

=

Actionable Context

```

---

# Context Package Structure

```
# Context Package

ID:

Title:

Owner:

Date:

Status:


## 1. Objective


## 2. Background


## 3. Current Situation


## 4. Scope


## 5. Constraints

## 7. Assumptions


## 8. Previous Decisions


## 9. Required Analysis


## 10. Expected Output


## 11. Validation Criteria


## 12. Related Knowledge

```

---

# 1. Objective

Defines:

- what needs to be achieved
- why it matters
- desired outcome

---

# 2. Background

Provides:

- historical information
- previous conditions
- relevant events

---

# 3. Current Situation

Defines:

- actual condition
- observed problems
- current status

---

# 4. Scope

Defines:

Included:

- required areas

Excluded:

- boundaries

---

# 5. Constraints

Document:

- technical limitations
- budget
- time
- standards
- resources

---

# 6. Available Information

Include:

- drawings
- reports
- measurements
- photos
- calculations
- references

---

# 7. Assumptions

Every assumption should identify:

```
Assumption

Reason

Confidence Level

Validation Needed

```

---

# 8. Previous Decisions

Capture:

- previous choices
- reasons
- consequences

---

# 9. Required Analysis

Define requested activities:

Examples:

- evaluate options
- calculate requirement
- review compliance
- identify risks

---

# 10. Expected Output

Define deliverable type:

Examples:

- engineering report
- recommendation
- calculation
- decision support

---

# 11. Validation Criteria

Define how success is measured.

Examples:

- accuracy requirement
- standard compliance
- review approval

---

# Context Quality Rules

A valid Context Package must be:

## Complete

Contains required information.

---

## Focused

Avoids unnecessary data.

---

## Traceable

Sources are identified.

---

## Current

Reflects actual conditions.

---

# Context Reuse

Completed packages should become future knowledge sources.

Examples:

```
Context Package

↓

Decision Record

↓

Lesson Learned

↓

Engineering Knowledge

```

---

# Anti-Pattern Prevention

## Starting Without Context

Creating analysis based on incomplete understanding.

---

## Context Dump

Providing large amounts of irrelevant information.

---

## Lost Decisions

Important reasoning remaining only in conversations.

---

## Repeated Investigation

Solving the same problem multiple times.

---
