# Purpose

This standard defines the evaluation criteria for determining whether a process, workflow, or capability is suitable for agent-based execution within the FDG Ecosystem.

---

# Core Principle

Not every task requires an agent.

Agents shall be created only when they strengthen organizational capability.

---

# Agent Creation Decision Rule

Before creating an agent, evaluate:

```
Business Objective

+

5R Readiness

+

Risk Assessment

+

Expected Value

```

---

# Engineering Objective Requirement

Every proposed agent shall begin with an objective.

The objective must define:

## Desired Outcome

What result should exist?

---

## Success Criteria

How will success be measured?

---

## Business Value

Why does this capability matter?

---

## Boundaries

What is outside the agent's responsibility?

---

# 5R Agent Readiness Assessment

A candidate capability shall be evaluated using:

```
Repetitive

Rules-Based

Repeatable

Reviewable

Return on Investment

```

---

# 1. Repetitive

Question:

Does this activity occur frequently enough to justify automation?

Consider:

- frequency
- workload volume
- recurring effort

Low repetition reduces agent value.

---

# 2. Rules-Based

Question:

Can the activity follow defined logic, criteria, or procedures?

Examples:

Suitable:

- report generation
- data classification
- standard analysis

Less suitable:

- undefined strategic judgment

---

# 3. Repeatable

Question:

Can similar inputs produce consistent workflows?

Consider:

- stable process
- predictable inputs
- measurable outputs

---

# 4. Reviewable

Question:

Can results be verified?

Required:

- acceptance criteria
- validation method
- human review where necessary

---

# 5. Return on Investment

Question:

Does the expected value exceed:

- development effort
- maintenance effort
- operational cost
- risk

---

# Readiness Scoring

Suggested evaluation:

## Ready

Strong evidence across 5R.

Proceed to design.

---

## Conditional

Some criteria incomplete.

Improve process first.

---

## Not Ready

Agent creation not justified.

Use another solution.

---

# Agent Alternatives

Before creating an agent, consider:

## Process Improvement

Can the workflow be simplified?

---

## Documentation

Is missing knowledge the real problem?

---

## Training

Does human capability need improvement?

---

## Traditional Automation

Is deterministic software sufficient?

---

# Authority Assignment

Agent authority shall follow:

```
Advisory

↓

Assisted

↓

Controlled Execution

↓

Trusted Execution

↓

Optimization

```

Authority increases only after validation.

---

# Agent Readiness Review

Before deployment verify:

✓ Objective defined.

✓ 5R assessment completed.

✓ Context available.

✓ Authority defined.

✓ Validation method exists.

✓ Risks evaluated.

✓ Owner assigned.

---

# Agent Retirement Review

Agents shall be retired when:

- objective is no longer valuable
- process changed
- maintenance exceeds benefit
- safer alternatives exist

---

# Anti-Pattern Prevention

## Agent First Thinking

Creating agents before understanding the problem.

---

## Automation Theater

Building impressive systems without measurable value.

---

## Uncontrolled Autonomy

Giving execution authority too early.

---

## Missing Reviewability

Creating outputs that cannot be verified.
