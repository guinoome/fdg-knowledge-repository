# Purpose

This standard defines how Nex Core Intelligence converts engineering information into structured, professional, and decision-ready reports.

---

# Core Principle

A report is not a record of activity.

A report is a tool for engineering decisions.

---

# Reporting Objective

Nex reports shall provide:

- accurate information
- clear analysis
- traceable evidence
- recommended actions

---


# 1. Report Classification

Reports shall be categorized:

---

# Technical Investigation Report

Purpose:

Analyze problems and determine causes.

Examples:

- equipment failure
- water quality issue
- system malfunction

---

# Engineering Assessment Report

Purpose:

Evaluate current condition.

Examples:

- equipment condition
- energy assessment
- system review

---

# Calculation Report

Purpose:

Present engineering calculations.

Examples:

- sizing
- capacity evaluation
- energy analysis

---

# Maintenance Report

Purpose:

Communicate maintenance status.

Examples:

- PM performance
- corrective actions
- recurring issues

---

# Executive Engineering Report

Purpose:

Support management decisions.

Examples:

- CAPEX justification
- risk assessment
- improvement proposal

---

# 2. Standard Report Structure

Recommended format:

```
Title

Document Information

Executive Summary

Background

Current Condition

Investigation / Methodology

Technical Analysis

Findings

Root Cause

Options Considered

Recommendation

Implementation Plan

Risk Consideration

References

Appendices

```

---

# 3. Executive Summary Requirement

Every major report should answer:

```
What happened?

Why does it matter?

What was found?

What should be done?

```

---

# 4. Evidence-Based Reporting

Reports should separate:

---

# Facts

Verified information.

Example:

Equipment operating data.

---

# Analysis

Engineering interpretation.

Example:

Possible cause evaluation.

---

# Conclusion

Final technical judgment.

---

# Recommendation

Proposed action.

---

# 5. Report Quality Requirements

Every report should be:

---

## Accurate

Information is technically correct.

---

## Traceable

Sources and assumptions identified.

---

## Understandable

Suitable for intended audience.

---

## Actionable

Leads to decisions.

---

# 6. Audience Adaptation

Reports should match audience needs.

---

# Engineering Team

Focus:

- technical details
- methods
- calculations

---

# Management

Focus:

- impact
- risk
- cost
- decision

---

# Executive Leadership

Focus:

- strategic value
- business impact
- recommendation

---

# 7. Recommendation Framework

Recommendations should include:

```
Issue

Proposed Solution

Expected Benefit

Required Resources

Risk

Priority

Timeline

```

---

# 8. Report Validation

Before release:

Verify:

- technical accuracy
- calculations
- references
- conclusions
- recommendations

# Anti-Pattern Prevention

## Data Dump Reports

Large information without analysis.

---

## Unsupported Recommendations

Solutions without evidence.

---

## Technical Reports Without Decision Value

Engineering detail without purpose.

---

## Automated Reports Without Validation

Fast but unreliable output.
