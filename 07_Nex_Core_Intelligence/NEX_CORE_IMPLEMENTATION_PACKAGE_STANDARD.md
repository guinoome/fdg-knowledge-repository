# Purpose

This standard defines the implementation structure required to deploy Nex Core Intelligence within the FDG Ecosystem.

---

# Core Principle

The repository is the foundation.

The intelligence layer is built on organized knowledge.

# Folder Responsibilities

---

# 00_Inbox

Purpose:

Temporary capture location.

Examples:

- ideas
- notes
- references
- observations

Rule:

Nothing important remains permanently here.

---

# 01_FDG_Identity

Contains:

- FDG mission
- organizational principles
- operating philosophy
- ecosystem architecture

---

# 02_Principles_and_Standards

Contains:

- NEX standards
- engineering standards
- governance documents

---

# 03_Engineering_Knowledge

Contains:

- technical references
- calculations
- methods
- engineering lessons

---

# 04_Projects

Contains:

- active projects
- project context
- deliverables
- technical history

---

# 05_Decision_Records

Contains:

- engineering decisions
- architecture decisions
- strategic choices

---

# 06_Workflows_and_Procedures

Contains:

- SOPs
- workflows
- operational methods

---

# 07_Nex_Core_Intelligence

Contains:

- Nex standards
- agent frameworks
- memory architecture
- intelligence models

---

# 08_Automation

Contains:

- automation designs
- scripts documentation
- workflow automation records

---

# 09_Templates

Contains reusable structures:

- reports
- decisions
- reviews
- context packages

---

# 10_Lessons_Learned

Contains:

- failures
- improvements
- operational learning

---

# 99_Archive

Contains:

- retired documents
- historical versions
- obsolete information

# Note Structure Standard

```

## Purpose

## Context

## Information

## Analysis

## References

## Related Notes
```

# Anti-Pattern Prevention

## Empty Architecture

Creating folders without usage discipline.

---

## Documentation Without Retrieval

Saving information nobody uses.

---

## Automation Before Structure

Automating chaos.

---

## Tool Dependency

Building around software instead of capability.
