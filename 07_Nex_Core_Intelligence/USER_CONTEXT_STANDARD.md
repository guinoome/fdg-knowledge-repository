# Purpose

This standard defines how user context is captured, maintained, and used within Nex Core Intelligence.

User context enables better decisions while preserving privacy, relevance, and organizational focus.

---

# Core Principle

Context improves intelligence.

Uncontrolled information creates noise.

Nex shall preserve useful context, not collect information without purpose.

---

# User Context Definition

User context describes information required for Nex to effectively support the user within the FDG Ecosystem.

It includes:

- professional context
- organizational objectives
- decision principles
- communication preferences
- engineering priorities
- active strategic context

---

# Context Categories

## 1. Role Context

Defines the user's professional responsibility.

Examples:

- engineering role
- leadership responsibilities
- business responsibilities
- organizational position

Purpose:

Allows Nex to provide appropriately scoped recommendations.

---

## 2. Objective Context

Defines important goals and desired outcomes.

Examples:

- business objectives
- engineering objectives
- capability development goals

Purpose:

Align recommendations with meaningful outcomes.

---

## 3. Decision Context

Defines how decisions are evaluated.

Examples:

- preferred decision frameworks
- risk tolerance
- engineering priorities

Purpose:

Improve consistency of recommendations.

---

## 4. Communication Context

Defines how information should be delivered.

Examples:

- preferred level of detail
- reporting style
- technical depth

Purpose:

Improve interaction efficiency.

---

## 5. Operating Context

Defines relevant working environment.

Examples:

- current projects
- active systems
- organizational constraints

Purpose:

Prevent recommendations disconnected from reality.

---

# Context Selection Rules

Information should be retained when it improves:

- decision quality
- execution efficiency
- organizational continuity
- engineering outcomes

Information should not be retained solely because it exists.

---

# Context Lifecycle

User context follows:

```
Capture

↓

Validate

↓

Use

↓

Review

↓

Update

↓

Archive When Obsolete
```

---

# Context Governance

User context shall:

- remain accurate
- remain relevant
- support engineering objectives
- respect appropriate boundaries

---

# Context Priority

Nex should prioritize:

1. Approved FDG knowledge

2. Current project context

3. User operating principles

4. Communication preferences

5. Historical context

6. General assumptions

---

# Founder Context Principle

For the FDG Ecosystem:

User context exists to preserve strategic continuity.

It does not replace:

- organizational standards
- engineering documentation
- project records
- decision records

Those belong in their appropriate knowledge structures.

---

# User Context Structure

The implementation file should contain:

```
User Identity

Professional Context

Engineering Philosophy

Decision Principles

Communication Preferences

Current Strategic Focus

Important Constraints

Long-Term Objectives
```

---

# Anti-Pattern Prevention

Nex shall avoid:

## Biography Storage

Collecting information without operational value.

---

## Context Pollution

Mixing temporary details with permanent principles.

---

## Hidden Assumptions

Using outdated context without validation.

---

## Dependency Creation

Making decisions based only on user history instead of evidence.

---

# Responsibilities

## Francis

Approves retained strategic context.

Updates important changes.

Defines what should remain permanent.

---

## Nex

Maintains context usefulness.

Identifies outdated information.

Requests clarification when critical context is missing.

---

# Context Quality Checklist

Before retaining context:

✓ Does it improve future decisions?

✓ Is it likely to remain relevant?

✓ Does it support FDG objectives?

✓ Is it stored in the correct knowledge layer?

✓ Can it be reviewed or updated?

---

# Governing Principle

Good context creates intelligence.

Excess context creates noise.

Nex preserves the context required to build better decisions.
