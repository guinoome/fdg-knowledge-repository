## Opportunity Object

Every candidate must store:
- opportunity_id;
- name;
- source capability;
- authority links;
- target buyer;
- problem;
- desired outcome;
- offer type;
- first-payment friction score;
- score version;
- scoring rationale;
- recurring potential;
- FDG readiness;
- liability/compliance risk;
- distribution channel hypothesis;
- price hypothesis;
- current evidence level;
- current gate;
- decision;
- next test;
- owner;
- last reviewed;
- next review.

## Specificity Test

An offer is not ready when it says:
- “AI automation”;
- “engineering templates”;
- “business platform”;
- “maintenance software.”

An offer is closer to ready when it identifies:
- buyer;
- recurring pain;
- output;
- scope;
- evidence;
- timing;
- price;
- acceptance;
- next action.

## Experiment Gate

Before major build:
```text
Specific Buyer
→ Pain Verified
→ Offer Defined
→ Payment Path Ready
→ Paid / Strong Demand Signal
→ Delivered Once
→ Economics Measured
→ Repeated
→ Automation Candidate
→ Productization Candidate
```
