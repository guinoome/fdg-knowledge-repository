## Implementation-Grade Screen Extension — 2026-10-10

In addition to the original fields, material screens should define:

- user goal;
- information hierarchy;
- primary action;
- secondary actions;
- role projection;
- device context;
- desktop layout behavior;
- mobile layout behavior;
- tablet behavior where applicable;
- partial-data state;
- read-only state;
- offline state;
- syncing state;
- conflict state;
- attention/critical state;
- evidence drill-through;
- recovery after failure;
- accessibility requirements;
- performance/NFR requirements;
- analytics/telemetry if justified;
- linked requirement IDs;
- linked acceptance criteria;
- test IDs.

Required screen states are not optional visual polish. They are part of implementation readiness.
