# FMCIS — Current Design Recap

## Agreed principles

1. FMCIS dynamically assembles capability teams; it does not permanently define a fixed team.
2. Chief of Staff / Lead Coordinator translates intent into coordinated work but has no authority above Nex.
3. Nex remains the FDG Architecture & Intelligence Authority.
4. Nex may be offline during the current implementation phase without blocking FMCIS.
5. Francis performs the review/approval gate while Nex is not continuously online.
6. A Founder decision may bypass a Nex recommendation and must be informed to Nex as learning context.
7. Chat collaborators are primarily useful for planning, independent thinking, research, comparison, and debate.
8. Agent environments such as Claude Code and Codex are primarily execution environments and may use their own skills, agents, models, connectors, and parallelism.
9. FMCIS chooses capability; it should not recreate each collaborator's internal orchestration system.
10. Model allocation must be capability-weighted.
11. Do not maximize agents. Maximize useful intelligence per unit of time, token, and cost.
12. Agents apply Loop Engineering until defined acceptance criteria are satisfied.
13. Consensus is not truth; evidence quality determines resolution.
14. Every failed loop must produce information that improves the next loop.
15. FMCIS maintains engagement memory.
16. The future dashboard should eliminate permanent manual copy/paste.
17. The dashboard should eventually become FMCIS intake, coordination, observability, memory, and approval workspace.
18. GitHub is read-only reference; the working system is local.

## Core statement

> **Nex is always on top, but Nex is never above learning.**
