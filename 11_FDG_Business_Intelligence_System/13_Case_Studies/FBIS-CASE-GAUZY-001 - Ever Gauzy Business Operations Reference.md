## 2026-10-26 — Original FDG REST port laboratory outcome

**Developer/user decision:** Evaluate an **FDG-owned, provider-replaceable REST adapter** as a lower-coupling approach. Gauzy publishes [REST/Swagger API documentation](https://docs.gauzy.co/api/overview/) and [project response example](https://docs.gauzy.co/api/project-endpoints/). [Gauzy's licensing wiki](https://github.com/ever-co/ever-gauzy/wiki/Licensing) recognizes that REST between separate programs is *normally* interprogram communication, while warning that intimate coupling can still create a combined/derivative work. **Neither technical feasibility nor a REST boundary constitutes legal clearance.**

**Actual original code and test (in unmerged research PR):** [FDG PR #19](https://github.com/guinoome/fdg-knowledge-repository/pull/19), branch `evaluation/gauzy-rest-provider-port-20261026`, was developed as isolated, read-only FDG JavaScript code and a deterministic local-provider alternative. FDG's working `/account/`, subscribed branch access, Supabase auth/billing and Fuel module were **not modified** and do not import the new integration module. The test fixture uses no real tokens, request to Gauzy or proprietary client data.

**Measured reproducible synthetic result:** [GitHub Actions run 40244833091](https://github.com/guinoome/fdg-knowledge-repository/actions/runs/40244833091), exact tested code HEAD `75402768f87898f1a342c22079e0e610e2fafaea`: **13/13 Node.js 22 tests passed**, including normalized project view, replacement with offline local provider, explicit provider-host allowlisting, HTTPS, one-org scoping, missing/invalid token, 401/403/429 rejection and invalid response/pagination. Following that code test, a **documentation-only commit** was added to the draft PR; no post-doc code changes.

**Limitations before functional acceptance:** Existing user session and subscribed branch to Gauzy organization mapping is not implemented; neither a legal release of AGPL source nor an actual licensed Gauzy API credential/endpoint, schema compatibility, timeout/egress policy, real offline sync or app-level UAT was tested. FLIS, FSIS and FBIS maintainers must decide the exact arrangement and approve the bounded read-only integration before production code wiring. No valid real-world integration, revenue or client acceptance is claimed. **Disposition:** `FDG_OWNED_ADAPTER_TESTED_ON_SYNTHETIC_FIXTURES / LICENSE_REVIEW_PENDING / LIVE_INTEGRATION_NOT_AUTHORIZED`.

[FMIS draft PR #18](https://github.com/guinoome/fdg-knowledge-repository/pull/18) separately tests fail-closed actorless maintenance terminal transitions (19/19 real FMIS SQLite and UI regression tests, [Actions 40244442672](https://github.com/guinoome/fdg-knowledge-repository/actions/runs/40244442672)), with engineering-owner decision and release acceptance still pending.
