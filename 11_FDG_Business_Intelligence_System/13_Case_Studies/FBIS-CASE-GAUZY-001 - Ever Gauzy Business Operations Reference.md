# FBIS-CASE-GAUZY-001 — Ever Gauzy external benchmark

**Founder context:** Follow-up to the founder's requested Ever Gauzy GitHub platform review. This captures only evidence useful for FDG's already-defined Business Platform, payroll/workforce, engineering service delivery and governed specialist-agent integrations. It is **not** a competing FDG ERP architecture, approval of third-party code or assignment of new app development.

## Existing FDG authority; avoid duplication

- **FBIS:** `[[11_FDG_Business_Intelligence_System/06_Business_Architecture/FBIS-ARCH-CBC-001 - FDG Common Business Core Architecture|FDG Common Business Core]]` owns shared customer, service/product, employee, sales, bill/invoice and account concepts. Compare with the existing [[11_FDG_Business_Intelligence_System/13_Case_Studies/FBIS-CASE-DIZLOG-001 - DizLog Business Platform Reference|DizLog]] and [[11_FDG_Business_Intelligence_System/13_Case_Studies/FBIS-CASE-ODOO-OGIS-001 - Odoo OGIS Hospitality Reference|Odoo]] studies; Gauzy primarily adds evidenced **person/time → project cost, org-scoped authorization and event/agent contracts**.
- **FDG Payroll:** Keep the independent portable/offline workspace, locked posting and documented correction/reversal controls, locally valid payroll and real HR Head approval. Gauzy's approval status and arithmetic implementation are **references only**; statutory compliance and separation-of-duties require FDG-specific rules and tests.
- **FBPOIS/FM​IS:** Maintain engineering asset/PM/WO source of truth, facility permission scopes and independent FWIS OOO/OOS clearance. Gauzy's generic tasks and monitoring do not establish engineering maintenance sign-off. **Issue #11** stays separate; Gauzy does not close an unaccepted FMIS authority defect.
- **FMCIS/FPJIS/FSIS:** Nex orchestrates bounded approved tool operations; a separate runtime must authenticate each principal, branch/company and action, enforce human confirmation for consequential actions and retain reproducible acceptance evidence. No generic “AI employee” inherits permissions.

## Smallest future experimental workflow, NOT BUILD_AUTHORIZED

**Synthetic one-customer monthly engineering-service delivery:** qualified lead → approved service quote → created project → assigned engineer → time/material capture → reviewed cost → invoice → payment status → one evidence-linked margin report. Initial comparison should be done against the **existing FDG workflow and files**; identify an actual missing step and implement only that step if owner authorizes. Expected negative tests: cross-business/branch denial, unauthorized quotation/invoice approval, mismatched labor timestamps, duplicate invoice/payment event, offline restart, reversal/adjustment, secret leakage through MCP and rate/price tampering. Only human-reviewed results on exact code can become `FUNCTIONALLY_ACCEPTED_BOUNDED`.
