## REUSE / EXTEND / MERGE / REPLACE / NEW

**Decision: EXTEND the existing governed capabilities; NEW only this evidence-level source-register record.** The videos do not authorize new top-level systems, fictitious “hired” employees, direct third-party skill installation, always-on agents or externally published data.

1. **Five marketed employee roles → existing FDG capability profiles (video 2193).**
   - “Chief of staff” → **Nex as orchestrator**, with time-bounded briefing and delegated task ledger, not a new autonomous executive.
   - “Social media” → [[FCMIS/FCMIS-Social-Publishing-Routine-Growth-Operations|FCMIS editorial pipeline]], using FDG engineering claims cleared by FEIS and real publishing receipts.
   - “AEO + SEO” → [[18_FDG_External_Intelligence_System/FEXIS-MASTER-INDEX|FEXIS discoverability]], with independently measurable search/referral outcomes and no guaranteed rankings.
   - “Sales” → existing [[03_Agentic Framework/FDG_BUSINESS_SPECIALIST_AGENT_CAPABILITY_PROFILES_2026-10-09|commercial specialist governance]] plus FBIS handoff from qualified prospect to proposal/accepted payment; not mass unsolicited contact.
   - “Video editor” → FDG Creative Studio/FCMIS, preserving original graphics, engineering quantities/units, accessibility captions, platform approvals, and rights.
   - **Common acceptance contract:** versioned role and scope, accountable human, allowed sources/connectors, evidence/output schema, task receipt, negative permission test, approval state, provider fallback and measured client/business result. “AI employee” is a *capability label* until staffed with a verified working runtime.

2. **Practical AI curriculum → FDG bounded agent onboarding (video 2215).** Use the observed concepts to teach collaborators a progression: retrieve current domain authority → explain the smallest user outcome → operate approved tools against synthetic/local data → wire a restricted adapter → produce a verifiable artifact → add human decision boundary → test exceptions and rollback → record source-to-build results. Assess trainees by **actual reproducible output**, not tutorial completion or assumed tool availability. Route through [[03_Agentic Framework/FDG_PROJECT_START_SKILLS_SECURITY_GATE_2026-10-25|P0 skills preflight]] and [[20_FPJIS_FDG_Project_Intelligence_System/35_Core_Completion_and_Roadmap/17_Requirements_View_Compilation_and_Agent_Acceptance_Standard|FPJIS source-to-acceptance gate]].

3. **“Loop engineering” → existing FMCIS/FPJIS review discipline (video 2217).** A loop has explicit user outcome, owning agent, exact input revision, test fixture, allowed steps, budget/time cap, independent inspector and stop states `APPROVED / REVISE / BLOCKED / FAILED / SKIPPED / STAGED`. Retries may not change protected product semantics, role permissions, engineering rules or accepted source requirements. Changes to an inspected diff invalidate prior signoff. Log a reproducible issue and hand it to the real owner rather than endlessly self-revising. Existing owner: [[21_FDG_Multi_Collaborator_Intelligence_System/01_Architecture/FMCIS-005_Loop_Termination_Criteria|FMCIS-005]]. A tool-generated “passed” graphic is not a test receipt.

4. **App-integrated workflow → FWAIS adapter contract (video 2218).** Author one tool-neutral workflow:
   `authorized source event/schedule → scoped read adapter → validate completeness + provenance → deterministic transformations → optional assistant draft → independent rule/approval gate → bounded output destination → delivery receipt → outcome reconciliation`.
   Required fields: `workflow_id`, `run_id`, `trigger_id`, `source_record_ids`, `source_revision`, `tenant/branch scope`, `purpose`, `approval_state`, `idempotency_key`, `delivery_receipt`, `redacted_error` and `retry_deadline`. An n8n diagram, Slack message, HubSpot mockup or model draft is **not** evidence of production integration. Keep provider adapters replaceable and an offline/local CSV/queue pathway for permitted tasks. Follow [[19_FWAIS — FDG Workflow Automation Intelligence System/04_Integration_Intelligence/05_Integration_Patterns/FWAIS_Adapter_Architecture|FWAIS adapter architecture]] and [[19_FWAIS — FDG Workflow Automation Intelligence System/05_Agentic_Workflow_Engineering/04_Human_in_the_Loop/FWAIS_Human_in_the_Loop|human approval rules]].

5. **Operational occupancy forecast → privacy-safe FBPOIS/FWIS engineering-readiness candidate (screenshot).** Model **per-unit per-local-date status**, not an untyped color-filled table: `CONFIRMED_OCCUPIED`, `CONFIRMED_AVAILABLE`, `RESERVED`, `OUT_OF_SERVICE`, `UNKNOWN`. A blank cell is `UNKNOWN`, **not evidence of vacancy or readiness for maintenance**. Import uses authorized source and effective timestamp, original status mapping, edit provenance and role-scoped view; reconcile forecast revisions. For a proposed preventive-maintenance window, validate the authoritative occupancy source and engineering/guest-services clearance before issuing work, isolate guest-identifiable data, and exclude contacts/guest records from general engineering briefings. This is a **candidate reusable pattern**, not a live interface to resort systems; the screenshot is not a permission grant.
