# TC01 — Test dossier source contract

2026-10-17 · Existing single-project offline Lifecycle Workspace · source baseline `dda8be1bedb0cd5265d56ef7989326b2eef4eebc`.

## Client task

A site engineer selects an existing work item and names a test package: two visible inputs. The workspace reuses that work identity. Record the actual readiness basis and test; a retest suggests the preceding method, criterion and reviewer for confirmation. It generates current blockers, the original failed/passed attempt trail and a printable test dossier source index. Prepare a Pending delivery, then record actual named receipt when the source checks are satisfied. Save the working HTML explicitly; JSON is an alternate backup/restore.

Essential engineering declarations still require actual references. No sample method, passing result, authority, evidence or receiver is fabricated.

## Ownership and format

All data remains in original TestPacks, Tests, Punch and Turnover registers. The56-register schema and version1 JSON are unchanged. Draft = planned; Accepted TestPacks = manually recorded readiness review; Passed Tests = actual recorded result; Accepted managed Turnover = scoped dossier receipt. These states do not confer operating clearance, whole-project acceptance, authenticated authority or maintenance readiness.

Reserved references:

One pack represents one test/retest chain in this slice. Use separate packs for independent tests. Generic legacy records are not silently tagged, migrated or newly accepted. Existing Daily reported/physically verified/QA accepted, billable, billed and paid states remain separate.

## Current source checks

- Unique active project/work/pack/test identities. Missing/duplicated references, competing/cyclic retests, archived predecessors, cross-work results or a retest before its predecessor block readiness.
- Actual procedure/version reference, prerequisite basis, hold/witness basis, readiness reviewer/date/evidence; no unresolved pack blocker. Review date at/before cutoff.
- Unique eligible latest test/retest; recorded pass plus method, criterion, observed/measured result with units as applicable, performer, reviewer/date and evidence. Result review cannot precede test or exceed cutoff. Test cannot predate readiness review. Managed pack revision must match.
- Relevant open or invalid Punch/NCR blocks. Unallocated project Punch/NCR conservatively blocks; no invented severity exceptions or acceptance authority.
- Punch Closed uses native owner, verified_by, verification_date and closure_evidence_ref. The normalized declared verifier must differ from the repair owner. A typed name is not proof of identity, competence or independence.
- Receipt needs the designated receiving person, actual receipt/authority evidence and actual date at/after test/readiness review and at/before cutoff. Pending can be prepared before readiness; receipt cannot.
- Advanced saves reuse receipt checks and cannot erase a managed dossier source link. Imported invalid final states remain visible with review flags/attention. Current projections never silently rewrite original records.

Future-dated test sources remain visible as excluded. A later source failure or revision retains the earlier dated receipt and flags its current basis for review. Corrections require an explicit source revision; receipt is not silently replaced.

## Evidence and limits

Criterion/tolerance, instrument/calibration and original engineering files remain controlled under real project authority; this slice indexes references and recorded observations. It is not the full CORE-0005 commissioning package. It does not assess every asset, O&M manual, as-built, training, spares, warranty, legal obligation or maintenance-ready domain. FEIS-MNT-0002 is a Proposed Engineering Standard and reinforces this separate boundary.

Names/declarations are manual. No authentication, permission enforcement, professional signature, automatic technical approval, attachment delivery, cloud sync or deployment is added.
