# ML-DEP Interactive Motion Invitation Platform — START HERE

Status: Baseline Candidate  
Repository: `guinoome/mlprinting`

## Mission
Evolve the existing ML Digital Event Platform into an **Interactive Motion Invitation Platform**.

> A digital invitation that feels like an experience.

> Beautiful enough to share. Interactive enough to remember. Practical enough to manage your event.

> Your digital invitation can match your printed invitation.

This is an evolution of the current repository, not a rewrite.

## Governing lifecycle
`Blueprint → Cross-Intelligence Consultation → Visualization → Review → Baseline → Implementation → Validation → Learning`

## Hard product rules
- Customer journey: `Choose → Fill → Upload → Preview → Approve → Pay → Done`.
- Maximum personalization with minimum decision burden.
- Customer edits event data, media and approved optional modules.
- Customer does not edit animation choreography, motion timing, responsive layout or interaction logic.
- One reusable experience engine; never one application per invitation design.
- Templates become configuration-driven experiences.
- Digital invitations target meaningful motion (M2–M4); static is print/fallback, not the digital goal.
- Original media is always preserved. `Use Original` is default; `Remaster` is optional.
- No guest personal details in marketing.
- Political/campaign projects may be supported but are excluded from automatic public portfolio display.
- Before/during/after-event lifecycle is part of the product.
- Production Supabase is never an undocumented manual-edit environment.

## First coding milestone
Do not build all 50 designs first.

Build:
1. Experience Configuration Seam.
2. One Gold Standard Motion Invitation:
   `Opening Reveal → Motion Hero → Countdown → Story/Programme → Gallery → Music → Venue/Map → Calendar → RSVP → Share → QR`.
3. Extract reusable motion and interaction primitives.
4. Prove 3–5 differentiated experiences.
5. Then scale the 50-design catalogue.
