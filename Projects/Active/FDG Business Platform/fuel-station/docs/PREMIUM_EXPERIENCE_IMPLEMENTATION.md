# Fuel Station Premium Experience Implementation Brief

**Governed by:** [[17_FDG_Platform_Intelligence_System/07_Platform_Experience_Design_Intelligence/03_FDG_Premium_Experience_Design_and_Implementation_Mandate|FDG Premium Experience Design & Implementation Mandate]]
**Accepted visual:** ![[Projects/Active/FDG Business Platform/fuel-station/design/reference/fpis-fuel-operations-sample.png]]

## Forward-patch decision

Preserve the verified workbook model, closeout, delivery, wet-stock, pricing, reporting, safety, audit, and role-preview behavior. Add a connected prospect experience, stronger fuel-specific composition, mobile command navigation, explicit local/offline states, centralized branding, and evidence-aware value storytelling. Do not replace the framework or invent integrations.

## Experience architecture

1. **Prospect story:** outcome → fuel visual → verified proof → controlled workflow → scale path → locally generated review brief.
2. **Operational command:** station condition → next decision → explainable movement → closeout/action → evidence and exceptions.
3. **Mobile workflow:** compact command header, sticky bottom navigation, thumb-reachable primary action, stacked decisions, no information loss.
4. **Trust layer:** Workbook Verified, Local Demo, Concept, and Planned Capability never blur into “live.”

## Design system inventory

- **Palette:** true white operational surfaces; near-black green command surfaces; lime action; protected green/amber/red/blue/gray semantics.
- **Type:** local Segoe UI/Arial; editorial 42–72 px prospect headline; compact operational labels; readable mobile body copy.
- **Container model:** full-bleed prospect bands, one dominant hero media frame, open proof rails, operational canvas, compact ledgers; avoid uniform card grids.
- **Signature motifs:** diagonal FDG slash, green canopy line, fuel-flow line, numbered workflow rail, evidence source label.
- **Motion:** short reveal and progress transitions only; disabled under reduced-motion.
- **Imagery:** accepted FPIS fuel concept and micro-station showcase as labelled concept/product media; controls remain code-native.
- **Navigation:** public prospect header, existing command rail for operations, sticky mobile dock for the highest-frequency paths.

## Core states

- Public prospect view
- Verified workbook evidence
- Local demo
- Offline-ready / local save
- Validation error / held for review
- Successful local save
- Permission restricted
- Empty local history

## Client value proof

- Explain each recorded liter through sales, deliveries, calibration, and adjustments.
- Surface broken formulas and negative totalizer movement instead of hiding them in totals.
- Turn daily closeout into a reviewable workflow rather than a fragile spreadsheet sequence.
- Preserve a single-site path that can extend to branch and network visibility without redesigning the operating model.

## Deliberate deferrals

- No fabricated CCTV, automatic tank gauge, POS, payment, weather, or sensor feed.
- No external inquiry submission; prospect CTA prepares a local review brief only.
- No unverified 3D digital twin.
- No secure authentication or server-enforced authorization in the local prototype.
- No BIR or regulatory compliance claim.

## Acceptance checks

- Value and fuel domain are understood within the first phone viewport.
- Prospect enters working operations in one action.
- Workbook proof and demo data remain distinct.
- Closeout remains functional after the experience patch.
- 390 px has no page-level horizontal overflow.
- Public and operational views share identity without sharing the same layout.
