# Purpose

This standard defines the appropriate use of tags within the FDG Knowledge Repository.

Tags provide supplemental classification.

They do not define repository architecture.

---

# Core Principle

Repository architecture shall never depend upon tags.

Tags enhance discovery.

Architecture provides organization.

---

# Objectives

Tags shall:

- improve search
- support temporary grouping
- assist automation
- simplify filtering

Tags shall not replace:

- repository structure
- Maps of Content
- metadata
- engineering relationships

---

# Appropriate Uses

Tags may be used for:

knowledge status

temporary initiatives

workflow states

review queues

automation triggers

organizational reporting

Examples:

Review Required

Draft

Archive Candidate

Solar

Hotel

Research

---

# Inappropriate Uses

Tags shall not be used to replace:

repository hierarchy

engineering domains

document ownership

governance

organizational structure

permanent navigation

If a concept requires long-term navigation, it should become part of the repository architecture rather than a tag.

---

# Tagging Rules

Use the minimum number of tags required.

Avoid duplicate meanings.

Avoid overlapping classifications.

Prefer metadata when structured information is required.

Prefer links when relationships are required.

Prefer Maps of Content when navigation is required.

---

# Controlled Vocabulary

Repository tags shall use an approved vocabulary.

Synonyms shall be avoided.

Example:

Approved

Not

ApprovedDocument

ApprovedDoc

Final

Finished

Consistent terminology improves search quality.

---

# Responsibilities

Francis

Approves repository tagging conventions.

---

Nex

Maintains tag consistency.

Detects redundant tags.

Recommends migration of frequently used tags into formal repository structures when appropriate.

---

# Quality Checklist

Before introducing a new tag, verify:

✓ Is metadata more appropriate?

✓ Is a link more appropriate?

✓ Should this become a Map of Content?

✓ Should this become a repository section?

✓ Is the tag temporary or permanent?

---

# Organizational Principle

Tags are convenience features.

Repository architecture is organizational infrastructure.

Infrastructure shall always take precedence.

---

# Continuous Improvement

The approved tag vocabulary shall evolve through controlled governance.

Unused, duplicate, or obsolete tags should be retired to preserve repository clarity.

---

# Governing Principle

The FDG Knowledge Repository shall be navigated through architecture, not through tags.
