# FEIS-CM-0007 — Construction Manager Embedded Learning and Competency Standard

**System:** FDG Engineering Intelligence Systems (FEIS)  
**Domain:** Construction Management  
**Status:** Approved Direction — Architecture Extension  
**Owner / Final Authority:** Francis  
**Effective:** 2026-10-04

## Purpose

Turn the Construction Management module into a system that not only stores work, but progressively teaches qualified users how FDG expects that work to be performed.

The objective is organizational capability preservation, not generic AI education.

## Core Principle

> Learn in the governed workflow, then prove competence through real controlled work.

The system should reduce dependence on informal mentoring, tribal knowledge and repeated explanation when engineers or managers transfer, resign or join mid-project.

## Relationship to Personnel Continuity

[[08_FEIS_Engineering_Intelligence_Systems/02_Construction_Management/FEIS-CM-0003 - Project Continuity and Personnel Handover Standard|FEIS-CM-0003]] answers:

- what happened
- what is pending
- why
- what evidence exists
- what must happen next

This standard adds:

- how FDG expects the role to execute the next task
- what knowledge is required
- what evidence proves the task was performed correctly
- what the user still needs to learn or demonstrate

## Role Profiles

The module may maintain governed role profiles such as:

- Construction Manager
- Project Manager
- Site Engineer
- Project Engineer
- QA/QC Engineer
- Safety role
- Quantity Surveyor / Cost Engineer
- Planner / Scheduler
- Document Controller
- Procurement / Materials
- Commissioning Engineer
- Turnover / Closeout Coordinator

A profile defines capability requirements, not a person's professional license.

## Adaptive Onboarding

When a user enters a project, onboarding should consider:

- assigned role
- project type
- lifecycle stage
- discipline
- current responsibilities
- prior completed internal capabilities
- project-specific systems
- open work inherited
- jurisdiction
- risk level

The system should skip irrelevant material and prioritize what the person needs for current work.

## Learning Unit Pattern

A reusable learning unit should contain:

1. **Why it matters**
2. **Governing FDG standard**
3. **When to use it**
4. **Required inputs**
5. **Correct workflow**
6. **Common failure modes**
7. **Evidence required**
8. **Approval boundary**
9. **Practice example or sandbox**
10. **Real-work application**
11. **Verification / assessment**
12. **Related knowledge**

The learning unit should link to the actual operational workflow whenever possible.

## Embedded Guidance Modes

### Explain This Step

Explain the current form/workflow field using repository knowledge.

### Show Example

Show an original, non-client-confidential example consistent with the governing schema.

### Check My Work

Review the draft for completeness and evidence without silently approving it.

### Why Is This Blocked?

Explain missing prerequisites or approval dependencies.

### Teach Me Before I Continue

Launch the shortest relevant learning unit for the current task.

### Successor Mode

For a replacement employee, combine continuation brief + role guidance + open-task walkthrough.

## Competency Evidence

Possible evidence of internal capability:

- completed guided workflow
- correct use of required evidence
- passed knowledge check
- reviewer confirmation
- successful sandbox scenario
- approved real-work output
- demonstrated correct handling of conflict/unknowns
- completion of required safety/quality/contractual controls

Do not infer professional competence solely from time spent in lessons.

## Competency States

Suggested internal states:

- Not Introduced
- Introduced
- Practiced
- Demonstrated
- Verified
- Needs Refresh
- Superseded

These are organizational learning states, not statutory licenses or external professional credentials.

## Credential Boundary

FDG may issue internal completion evidence or training records.

Do not represent an internal module completion as:

- PRC licensure
- statutory qualification
- professional accreditation
- legally required training certificate

unless FDG has the necessary authority/accreditation for that specific credential.

## Knowledge Return Loop

When a user encounters a new situation:

Operational Work  
→ Exception / Lesson  
→ Review  
→ Approved Knowledge Improvement  
→ DCKL object / Task Pack update  
→ Future embedded guidance

This turns project execution into organizational learning.

## Manager Visibility

Authorized managers may view capability readiness at an appropriate level:

- role coverage
- critical capability gaps
- upcoming responsibility vs readiness
- successor readiness
- required refresher
- repeated workflow errors

Avoid reducing people to simplistic scores. Evidence and consequence matter more than gamification.

## Offline / Field Capability

Critical learning guidance required for field work should be cacheable where practical.

Offline access must not create an uncontrolled duplicate knowledge base. Sync and version rules apply.

## Provider Independence

Learning content, competency states, assessments and workflow definitions belong to the FDG Knowledge Repository / governed platform.

A language model may explain or personalize the material but must not be the sole keeper of it.
